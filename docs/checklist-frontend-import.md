## (백엔드용) 판정 가이드

| 항목 | 답변 | 이식 작업량 영향 |
|---|---|---|
| 프레임워크 | Vite React | 그대로 이식 — 최소 |
| | Next.js | 컴포넌트만 적출, 라우팅·이미지 최적화 등 껍데기 재작업 — 중 |
| React | 19.x | 그대로 |
| | 18.x | 의존성 호환 확인 필요 — 소 |
| 지도 | Leaflet/OSM | 키 불필요, 온프레미스 유리 — 최소 |
| | Mapbox/Google | 토큰·과금·오프라인 납품 검토 필요 — **별도 결정 사항** |
| 데이터 | 하드코딩/JSON 목 | 계약 타입으로 매핑만 — 소 |
| | 컴포넌트 안 fetch | 데이터 접근 적출 필요 — 중 |
| 스타일 | Tailwind 등 일관 시스템 | 기존 스캐폴드가 백지라 그대로 수용 — 최소 |
| 상태관리 | Zustand | 기존 스택과 동일 — 최소 |
| 라우팅 | 멀티 페이지 (4개 화면 확정) | react-router 도입 + features/{dashboard,best-frame,data,redmap} 분할 — 소 |
| 영상/프레임 뷰어 | `<video>`/이미지 | 프레임 전달 방식이 계약에 없음 — **BEST FRAME 계약 설계 선행 필요** |
| 히트맵 | 지도 내장 | 최소. 별도 라이브러리면 지도와의 좌표 동기화 확인 |

추가 참고: BEST FRAME / DATA / REDMAP은 아직 데이터 계약(REST·MQTT)이 정의되지 않았다. 이식 시 이 세 화면은 기획자의 목 데이터를 임시 유지하고, 화면별 계약 정의(각각 별도 티켓) 후 순차적으로 훅에 연결한다 — DASHBOARD를 먼저 완결하는 순서 권장.
